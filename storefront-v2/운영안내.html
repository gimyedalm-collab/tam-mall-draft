# 탐뷰티 공식몰 운영형 v2

## 완료한 파일
- 25개 로컬 미리보기: 홈, SHOP, ABOUT, 두 라인, 룩북, 상품 상세 14개, 검색, 장바구니, 주문서, 로그인, 쿠폰함.
- 상품 상세의 옵션 선택 → 미리보기 장바구니 → 수량 변경/삭제 → 주문서 확인. 가격은 수집 시점 스냅샷입니다. 개인정보 입력·실제 결제·실제 쿠폰 발급은 없습니다.
- 카페24 기본 상품 이미지 변수와 관리자 진열 순서를 보존합니다. 관리자에서 이미지를 바꾸면 기본 목록 이미지가 바뀌며, 코드가 이를 덮어쓰지 않습니다. 미리보기의 선정 이미지와 실제 관리자 이미지는 다를 수 있습니다. 처음 적용할 때 미리보기 이미지로 맞추려면 해당 상품의 목록 이미지를 관리자에 등록합니다.
- 카페24용 공통 헤더/푸터와 섹션을 별도 파일로 분리했습니다. 구매 화면의 모듈·옵션·폼·스크립트는 원래 스킨을 보존하고 범위가 제한된 CSS를 추가합니다.
- integrate_skin.py: 기존 스킨 원본을 읽어 별도의 적용 후보 폴더를 만듭니다. 실제 스킨 원본으로 실행한 상태는 아닙니다.

## 적용 순서
1. 카페24 디자인 관리에서 현재 PC/모바일 스킨을 백업·다운로드합니다. 같은 반응형 스킨인지 분리된 스킨인지 확인합니다.
2. 아래 명령을 실행하면 원본과 별개의 후보 폴더가 생성됩니다. output은 존재하지 않는 새 폴더를 지정합니다. 여러 스킨이 담긴 ZIP은 하나의 스킨 루트로 나누어 실행합니다.
   python integrate_skin.py --source "원본스킨.zip" --output "적용후보"
3. TAM_INTEGRATION_REPORT.json을 확인합니다. 헤더와 푸터를 각각 하나로 특정할 수 없는 레이아웃은 자동 변경하지 않고 manual로 남깁니다. 후보 파일도 최종 검수가 필요합니다.
4. 복사 스킨에 적용 후보를 반영합니다. /tam/index.html에서 새 홈을 확인합니다. 첫 화면 변경은 자동 수행하지 않습니다. /tam/assets의 이미지와 영상이 실제 URL에서 열리는지 확인합니다.
5. 원본 레이아웃의 CSS·JS·분석·앱 설정은 보존됩니다. 옛 메뉴 스크립트가 제거된 헤더 DOM을 전제로 하는지 개발자 도구에서 확인합니다. 잔존 사이드 메뉴/모바일 하단 메뉴는 원본에 따라 수동 정리합니다.
6. 상품 목록에서 상품명·판매가·품절 표시를 확인합니다. 현재 분류78/count200이며 필터는 출력된 상품만 대상으로 합니다. 상품 수 증가 시 분류별 서버 목록/페이지네이션으로 전환합니다.
7. 실제 회원/비회원, 색상별 품절, 수량 제한, 장바구니, 배송비, 쿠폰 중복/최소금액/제외상품, 결제 수단, 취소·복구를 복사 스킨에서 검수합니다. 결제 테스트는 테스트 수단을 사용합니다.
8. 주문서는 별도 카페24 스마트 주문서 설정/스킨을 사용할 수 있습니다. 현재 파일은 주문서 레이아웃의 색·테두리만 보수적으로 적용합니다. 실제 주문서 원본을 확인하기 전 구조 변경을 확정하지 않습니다.
9. 검수 완료 후 첫 화면/공통 링크를 실제 메인 경로로 전환합니다. PC/모바일 자동 이동과 검색 유입 상품 상세도 확인합니다.

## 현재 남은 필수 연결 작업
현재 카페24 관리자 접근 및 원본 스킨을 제공받지 않았습니다. 실제 모듈 컴파일, 회원 쿠폰 데이터, 배송/할인 계산, 결제, 리뷰 앱, 소셜 로그인은 실환경 검증 전입니다. 이 패키지를 바로 라이브에 올렸을 때 모든 기존 앱과 호환된다고 보장하는 상태는 아닙니다.
쿠폰은 임의의 할인율/조건을 만들지 않았습니다. 사용할 혜택이 정해지면 해당 값으로 관리자를 설정하고 주문서와 함께 검수합니다. 이미 발급한 쿠폰은 수정 가능 항목에 제한이 있습니다.
로컬 상품 상세 이미지 중 공식 서버에서 404였던 2장은 제외했습니다. 상세 원본 이미지는 작업 폴더의 캐시를 참조하며 적용 ZIP에는 포함하지 않습니다. Cafe24는 기존 상품 상세 내용을 사용합니다.
