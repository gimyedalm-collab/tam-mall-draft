# TAM 모바일 점검 — 2026-10-21

> 수정 전 감사 기록이다. 네 가지 결함의 수정과 재검증은 [수정 완료 기록](../mobile-fixes-20261021/REPORT.md)을 참고한다.

## 결론

기본 반응형 표시와 미리보기 구매 동선은 통과했다. 다만 모바일 최적화가
전부 완료된 상태는 아니다. 파우더 밤의 지연 로딩 누락, 320px 후기 번호 넘침, 공통 터치 영역,
작은 입력 글자를 먼저 개선해야 한다. 이번 기록은 점검 결과이며 수정 완료 기록이 아니다.

검사 기준: GitHub main `ac702df`의 동일 로컬 파일. Chrome 브라우저에서
320·390·430·768px의 25개 경로, 총100개 화면 조합을 검사했다.
공개 메인320px와 공개 파우더 밤390px도 별도로 확인했다.
실물 휴대폰, iOS Safari, Android Chrome의 실제 터치·키보드·저속 회선은 미검증이다.
Cafe24 운영몰 업로드와 실제 주문·결제는 기존 합의대로 보류 상태다.

## 확인된 정상 항목

- 정정: 100개 중14개 상품의320px 조합에서 후기 번호로2px 가로 넘침이 확인됐다. 나머지86개 조합은 가로 넘침이 없었다. 첫 화면의 로드 실패 이미지는 없었다. 문서 가로 넘침은 innerWidth가 아니라 documentElement.clientWidth와 비교했다.
  첫 화면 검사이며 모든 원격 이미지의 전체 스크롤 로딩을 보증하는 결과는 아니다.
- 14개 상품 상세, 메인, SHOP, 두 라인 목록, 검색, 브랜드, 룩북,
  로그인, 장바구니, 주문서, 쿠폰을 포함했다. 쉐이딩듀오는 읽기 검사만 했다.
- 메뉴 열기/닫기/Escape 및 메인 영상 일시정지 정상.
- 립 필터5개, 파우더 검색1개, 검색 결과 없음 안내 정상.
- 클라우드01 선택/수량2개에서28,800원, 미리보기 담기 후 같은 옵션·수량 유지.
- 장바구니3개 증량 후43,200원, 주문서 미리보기 이동과 합계 유지.
- 발색 비교 모달 열기/확대/닫기 정상. 확대 내용의 내부 스크롤은 문서 넘침을 만들지 않음.
- 새 상세 이미지의 첫 이미지 규격 지정과 기존 하단 구매바·안전영역용 CSS 유지.
- 제품 원본·발색·상세 디자인과 상거래 정책을 변경하지 않았다.

## 우선순위별 결과

### P1 — 파우더 밤14개 이미지에 지연 로딩 없음

- 위치: `storefront-v2/preview/product-111.html #product-detail`,
  `cafe24-delivery-20261020/powder-balm/index.html`.
- 전체14개 이미지11,506,686바이트, 약11.51MB. `loading="lazy"`가0개다.
- 공개 페이지에서 스크롤 전14개 이미지가 모두 로드됨을 확인했다.
- 다른 새 상세는 첫 이미지 이후 지연 로딩 적용: Cloud17/18,
  lip oil6/7, liner15/16, cheek8/9, highlighter13/14.
- 영향: 상세 하단까지 바로 읽지 않아도 데이터 사용과 초기 전송 경쟁이 발생한다.
  실제 저속 회선의 로딩 시간이나 Core Web Vitals 수치를 측정한 것은 아니다.
- 권장: 첫 가시 이미지 우선 로딩을 유지하고 아래 이미지에 지연 로딩 적용.
  납품 미리보기·생성기·메인 연결을 함께 수정해 재생성 시 되돌아가지 않게 한다.
- 대응: `$impeccable optimize`.

### P2 — 공통 터치 영역이 작고 모바일 로그인 숨김 규칙이 무효화됨

- 위치: `storefront-v2/preview/assets/ux-261013.css`, `tam.css`.
- 320px 공개 메인에서 검색 약21×44px, 로그인31×44px,
  장바구니41×44px, 영상 제어63×36px, 푸터 링크 높이33px.
- 미리보기 장바구니 수량 버튼40×40px.
- 모바일 `.ux-account` 숨김 규칙보다 `.ux-header a:not(.ux-logo)`가
  높은 선택자 우선순위를 가져 로그인 링크가 계속 표시된다.
- 영향: 좁은 헤더에서 터치가 빗나갈 여지가 있고 항목 밀도가 높다.
- 권장: 주요 조작 영역을44×44px 이상으로 확보하고 로그인은 이미 있는
  펼침 메뉴를 활용한다.44px는 이 점검의 사용성 목표이며 모든 미달 항목을
  곧바로 WCAG AA 위반으로 판정하지 않는다.
- 대응: `$impeccable adapt`.

### P2 — 입력·선택 글자가13px

- 위치: `tam.css`의 `.field`와 `font:inherit` 입력 규칙.
- 전체14개 상품의 옵션/수량, 로그인2개 입력, 주문서4개 입력·선택에서13px 확인.
- 영향: 옵션과 숫자의 모바일 가독성이 작다. iOS 키보드 표시·자동 확대는
  이 Chrome 뷰포트 검사로 검증하지 않았으므로 실제 발생했다고 단정하지 않는다.
- 권장: 모바일 입력·선택 글자를16px 수준으로 검토하고 옵션 길이와 키보드 노출을 실기기로 검증.
- 대응: `$impeccable adapt`.

### P2 — 미디어 용량과 모션 접근성의 남은 검증

- 메인 자동 재생 영상6,554,942바이트, 약6.55MB. `preload="auto"` 사용.
- 상세 전체 로컬 미디어 합계: liner11.62MB, highlighter11.49MB,
  powder11.51MB, Cloud6.00MB, cheek5.39MB, lip oil2.13MB.
  지연 로딩된 파일 합계는 첫 화면 다운로드량과 같지 않다.
- GIF 납품본에는 개별 일시정지 UI가 없으며 OS 모션 감소 설정에 대한 실제
  동작을 확인하지 않았다. 원본 영상에는 모션 감소 처리 코드가 존재한다.
- 권장: 실제 모바일 회선의 전송량·표시시간 확인, 원본 색/펄/제형을 보존하는
  범위에서 로딩 우선순위와 비트레이트 검토. GIF 대안을 임의로 적용하지 말 것.
- 대응: `$impeccable optimize`, 마지막 `$impeccable polish`.

## 참고 평가

모바일 점검 범위의 정성 평가이며 WCAG 인증이나 성능 벤치마크가 아니다.

| 영역 | 4점 만점 | 판단 근거 |
|---|---:|---|
| 접근성 | 2 | 메뉴·기본 라벨·Escape는 동작. 작은 조작 영역/입력 글자, GIF와 실기기 검증 부족 |
| 성능 | 2 | 대부분 지연 로딩. 파우더 밤 누락 및 큰 미디어 전송량 |
| 테마 일관성 | 3 | 기존 TAM 서체/색상 유지. 일부 CSS 값 중복. 다크모드는 요청 범위 아님 |
| 반응형 | 3 | 86개 조합 가로 넘침 없음. 320px 상품14개는 후기 번호2px 넘침. 실기기 미검증 |
| 구현 일관성 | 3 | 공통 UI와 원본 유지. 모바일 숨김 CSS 우선순위 충돌 |
| 합계 | 13/20 | 기본 동작 가능, 최적화 후속 작업 필요 |

기계 검사에서 Arial 사용에 대한 일반 경고1건이 나왔다. 기존 승인 디자인과
모바일 문제의 직접 근거가 아니므로 디자인 결함으로 채택하지 않았다.
별도 자동 브라우저나 새 도구는 설치하지 않았다.

### P2 — 320px 후기 페이지 번호 가로 넘침 (추가 정정)

14개 상품에서 clientWidth305px 대비 scrollWidth307px이며 오른쪽 다음 버튼 끝점은306.5px였다. 공개 product110에서도 재현했다. 기존 innerWidth320px 비교는 스크롤바 너비 때문에 이를 놓쳤으므로 clientWidth 기준으로 바로잡았다.
