# 첫 화면 좌우 여백 제거 — 2026-10-22

사용자가 좌우 여백을 거부하고 꽉 찬 첫 화면을 요청했다. 이전의 원본 전체 표시·화면 높이 제한 조합은 가로 화면에 여백을 만들었으므로 해당 선택을 변경했다.

- 가로형 화면: 폭 100%, 높이 100svh, `object-fit:cover`, 중앙 구도로 화면을 채운다. 비율 차이만큼 가장자리는 의도적으로 잘린다.
- 세로형 휴대폰·태블릿: 가로폭 100%와 원본 16:9 구도를 유지한다. 세로 전체 높이로 과도하게 확대하지 않는다.
- 투명 헤더, 스크롤·메뉴 열림 시 흰 헤더, 마지막 밝은 장면의 검은 내비게이션은 유지한다. 영상 바이트와 상품 상세는 변경하지 않았다.
- CSS 캐시 버전은 `261022fill`이다.

최종 화면 소스 `69d2172`. [Safari 검사 39705573263](https://github.com/gimyedalm-collab/tam-mall-draft/actions/runs/39705573263) 성공: 기존 50개 화면 검사, 홈 9개 크기, 저속 390px의 메인·쉐이딩·파우더 구매 UI 3개 검사 통과. 실제 홈 너비는 336/390/768/1440/1920/844/1366/2560/950px이며 macOS 창 제한으로 요청 320px은 336px이었다.

가로 영상의 왼쪽 0, 콘텐츠 전체 폭, 화면 높이 일치 및 가로 넘침 없음을 확인했다. 가로 태블릿·초광폭의 얼굴과 제품, 정사각형에 가까운 화면의 마지막 로고를 캡처로 검수했다. Windows Chrome 1920×911에서도 영상 1905×911px(스크롤바 제외), 왼쪽·상단 0을 확인했다. 이번 Chrome 크기 조절은 실제 너비가 1920px로 남아 모바일 검사로 계산하지 않았으며, 모바일 근거는 실제 390px Safari 결과다.

Cafe24 관리자는 다시 로그인된 상태이며 파일업로더 접근을 확인했다. 기존 격리 폴더 `/web/upload/tam-rollout-qa-20261021`에서 `06-ending.png` 첨부를 재시도했으나 같은 `-32000 Not allowed` 오류로 실패했다. 새 이미지 업로드, 상품 상세 저장, 운영 스킨 변경은 하지 않았다. 파일 URL 접근 권한 완료 답변은 아직 없으며, 실물 기기·후보 스킨의 네이티브 구매 연동 검증도 미완료다.
